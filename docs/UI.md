# UI: что есть, чего нет и что должно быть

Фронтенд — `src/frontend/` (ванильный JS + Leaflet, без сборщика и фреймворка):
`index.html`, `styles.css`, `app.js`. Сборка `npm --prefix src/frontend run build` просто
копирует три файла в `src/frontend/dist` (каталог в `.gitignore`), откуда их отдаёт тот же
axum-сервер из `WEB_DIR` (по умолчанию `./src/frontend/dist`), на своём origin. Отдельного
Node-сервера и CORS нет; `npm run dev` поднимает только python-стаб без API.

## Запуск

```bash
npm --prefix src/frontend run build
env MOCK_LLM=1 BIND=127.0.0.1:8080 cargo run --bin travel-ai
# http://127.0.0.1:8080
```

Проверка UI: headless Chromium по CDP гоняет `scripts/frontend_test.sh` — оболочка SPA,
рендер плана по SSE, отказ, контейнер карты и отсутствие горизонтального переполнения на
390 px:

```bash
BASE_URL=http://127.0.0.1:8080 bash scripts/frontend_test.sh
```

Полный локальный гейт — `bash scripts/qa.sh`: fmt, clippy, тесты, mock-сервер на 18090,
`smoke.sh`, браузерный тест и инварианты планирования.

## Визуальный язык

Светлая спокойная тема: белый и off-white поверхности, приглушённый бирюзовый акцент,
светлый hero с атмосферным градиентом и координатной сеткой, крупная типографика Unbounded,
карточки с мягкими тенями.

| Токен | Значение | Где |
|---|---|---|
| Ink | `#12211f` | основной текст |
| Ink soft / Muted | `#33463f` / `#6a7c78` | вторичный текст, подписи |
| Paper | `#ffffff` | панели, карточки, поля |
| BG / BG soft | `#f7f9f8` / `#eef3f1` | фон страницы, футер, сегменты |
| Teal / Teal deep | `#0f766e` / `#0b5c56` | акценты, активный транспорт, маршрут |
| Cyan | `#0e7490` | градиент заголовка hero |
| Amber / Danger | `#b45309` / `#b42318` | отказ / ошибка |
| Manrope | 400–700 | текст и интерфейс |
| Unbounded | 500–600 | заголовки и крупные цифры |
| Радиусы | 14 / 18 / 24 px | поля, карточки, панели и карта |
| Тени | sm / md / lg | карточки, панель формы, карта |

Полосы: hero → форма с превью-панелью → карта → план → футер. Заголовок 1–7 дней в
hero-stats, форма с счётчиком символов, примеры запросов, живой таймлайн этапов, карта в
скруглённой рамке, вертикальный таймлайн точек и отдельные секции «События дня» и
«Где остановиться».

Пользователь может явно попросить бары и клубы — тогда агент ищет категории
`bar`/`club`. В обычный маршрут ночные заведения не добавляются. Озёра и реки
используются как районы поиска, а маркеры ставятся на берегу.

## Что скрыто по просьбе команды

- Сводка модели (`plan.summary`) не выводится: она описывала служебные детали
  («N объектов из Википедии», «план состоит из sights/museum/historic»).
  Промпт дополнительно запрещает такое в `summary` и `note`.
- Предупреждение «Убрано повторяющихся точек: N» фильтруется в интерфейсе:
  это внутренний счётчик, остальные предупреждения остаются.
- Цены не показываются нигде: ни оценка стоимости в шапке плана, ни цены
  остановок, ни цены в карточках жилья (у нас они демонстрационные). Цены АЗС
  видны только в подсказке маркера и явно помечены «(демо)».

## Отели

Если инструмент `find_lodging` вернул варианты, бэкенд отдаёт **все** варианты в
`plan.lodging_options`, а выбранный — ещё и в `plan.lodging` / `days[].lodging_id`.
UI показывает список «Где остановиться»: номер, название, населённый пункт, тип,
цену за ночь, метки «в плане» и «рекомендация» (метка «рекомендация» достаётся первому
варианту, если он не выбран в плане). Если вариантов нет — секция скрывается.
Бронирования и внешних ссылок пока нет.

## События дня

`plan.days[].events[]` рендерятся отдельной секцией «События дня» под точками дня:
дата или диапазон дат, название, место и ссылка «Подробнее» только для http(s)-url.
У событий нет координат: маркерами и точками маршрута они не становятся.

## Состояния

- **Пусто** — форма, примеры и футер; карта инициализируется лениво при приближении к
  карточке, результатов нет.
- **Загрузка** — stages по мере событий SSE: «Проверяю тему → Разбираю запрос →
  Собираю план → Проверяю план → Готово»; «Упрощаю план» появляется, если план собран
  деградированным (fallback). Кнопка — «Собираю…».
- **План** — title, summary, pills (даты, транспорт, км, стоимость, до трёх дней погоды,
  предупреждения), вкладки дней, факты дня (точки, км, часы в пути, погода), точки с
  перегонами, события и жильё.
- **Отказ** — блок `#refusal`, без плана; HTTP при этом 200.
- **Ошибка** — красный блок с причиной и кнопкой «Повторить»; демо-подмены нет.
- **Даты** — нетронутые поля берут даты из intent и подставляются в форму после разбора
  (событие `intent`); изменённые вручную — главнее текста и уходят в запрос как есть.
- **Токен** — поле скрыто, пока `/api/health` не вернёт `auth_required:true`; 401 тоже
  открывает его.
- **Карта без библиотеки** — Leaflet грузится цепочкой jsDelivr → unpkg → cdnjs
  (события `leaflet-ready` / `leaflet-unavailable`, `window.__leafletState`). Если все
  три CDN недоступны, контейнер карты остаётся с подписью «Загружаю карту…», а дни и
  точки в списке рендерятся как обычно. Разметка `#map-fallback` в карточке есть, но
  текущий `app.js` её не заполняет.
- **Тайлы** — `tile.openstreetmap.org`; если за 6 секунд не пришёл ни один тайл,
  подпись меняется на «Карта недоступна — точки маршрута загружены».
- **Колесо мыши** — `scrollWheelZoom` включён (wheelDebounceTime 40 мс): пока курсор над
  картой, колесо зумит её; на тач-устройствах dragging/touchZoom выключены, страница
  скроллится жестом по карте.

## Что удалено по запросу

- Бейджи `мок` у точек и ночёвки.
- Бейдж `mock-llm` в шапке; вместо него `онлайн`.
- Контрол атрибуции Leaflet «Leaflet | © участники OpenStreetMap»; кредит
  «© OpenStreetMap · © CARTO» остался в углу карточки карты.
- Поле «Токен доступа» скрыто, если токен на сервере не задан.
- Панели «Проверка плана» и «Как собран план» убраны из UI; validation и trace доступны
  только в API (`/api/runs/{id}`).

## Что должно быть в API для UI

`POST /api/plan` (SSE) и `/api/plan/sync` принимают:

```json
{
  "query": "хочу к морю и маякам",
  "start_date": "2026-10-22",
  "end_date": "2026-10-24",
  "transport": "car"
}
```

- `query` обязателен, до 1000 символов.
- Даты необязательны, но передаются вместе; API проверяет диапазон 1–7 дней.
- `transport`: `car`, `foot`, `bike`, `transit`.
- Если даты не переданы, intent парсится из текста (по умолчанию 2 дня).
- `GET /api/health` отдаёт `auth_required`, чтобы UI не показывал токен зря.
- План отдаёт `days[].items[]`, `days[].legs[]`, `days[].events[]`, `weather[]`,
  `warnings[]`, `sources[]`, `lodging[]` (выбранное) и `lodging_options[]` (все варианты
  для блока «Где остановиться»).
- SSE-события: `stage`, `intent`, `tool_call`, `tool_result`, `plan`, `validation`,
  `usage`, `refusal`, `done`; UI использует `stage`, `intent`, `plan`, `validation`,
  `refusal`, `done`.

## Чек-лист ручной проверки

1. Открыть `/`, приблизиться к карточке карты — карта Приморья видна, zoom +/− работают, контрола атрибуции Leaflet нет.
2. Ввести «Хочу к морю и маякам», не трогать даты — план на столько дней, сколько разобрано из текста; поля дат синхронизируются с intent.
3. Сменить транспорт на «Пешком» — в meta и в intent транспорт `foot`.
4. Сменить даты на 1 день — план на 1 день, даты совпадают.
5. Ввести «Реши задачу по алгебре» — отказ, плана нет, HTTP 200.
6. Задать `APP_TOKEN` на сервере — поле токена появляется; без него — скрыто; при 401 поле тоже открывается.
7. Проверить карточку точки: под названием есть краткое описание (тип, часы, цена); клик ведёт к маркеру на карте (flyTo и попап), если точка прошла фильтр координат. Validation и trace остаются в API (`/api/runs/{id}`), но не показываются в UI.
8. Переключать дни: на карте — маркеры только активного дня; маркеров в море, озере или в точке `(0,0)` нет, вид подстраивается под точки дня.
9. Сузить окно до 390 px — горизонтального скролла нет, карта не уже 250 px.
