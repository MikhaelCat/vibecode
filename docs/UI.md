# UI: что есть, чего нет и что должно быть

Фронтенд — `src/frontend/` (ванильный JS + Leaflet), собирается в `src/frontend/dist`
и отдаётся тем же axum-сервером. Отдельного Node-сервера и CORS нет.

## Запуск

```bash
npm --prefix src/frontend run build
env MOCK_LLM=1 BIND=127.0.0.1:8080 cargo run --bin travel-ai
# http://127.0.0.1:8080
```

Проверка UI:

```bash
BASE_URL=http://127.0.0.1:8080 bash scripts/frontend_test.sh
```

## Визуальный язык

Стиль собран по референсу Heart Aerospace: монументальная типографика на
атмосферном градиенте, светлые full-bleed полосы, почти монохромная палитра,
нулевые радиусы и только outlined-действия.

| Токен | Значение | Где |
|---|---|---|
| Stratosphere | `#716e85` | градиент hero, подложка карты |
| Jetstream Blue | `#001489` | рамки кнопок/полей, активная вкладка, акценты |
| Onyx | `#000000` | текст, линии, футер |
| Cloud | `#ffffff` | фон контента, текст на градиенте/футере |
| Inter | 400/500/600 | вся типографика |
| Радиусы | `0` | все кнопки, поля, карточки, маркеры |
| Тени | нет | глубина только за счёт полос и градиента |

Полосы: hero → форма → карта → план → футер. Внутри — крупный заголовок,
текст слева, 40px поля, 70px между секциями. Никаких карточек с фоном,
скруглений и декоративных иконок.

## Все элементы

| Элемент | Селектор | Сейчас | Должно быть |
|---|---|---|---|
| Логотип `vibecode` | `.brand` | ссылка на `/`, перезагружает SPA | оставить; при клике сбрасывать форму/план |
| Регион | `.region` | статичный текст «Приморский край» | оставить |
| Статус | `#health` | `онлайн` после `/api/health`; без модели и `mock-llm` | `онлайн` / `нет связи`; при ошибке — причина |
| Текстовое поле | `#q` | обязательное, до 600 символов, placeholder | до 1000 символов (лимит API); счётчик; Enter не отправляет |
| Дата «С» | `#start_date` | по умолчанию завтра; native date | русский формат; блокировать прошлые даты |
| Дата «По» | `#end_date` | по умолчанию +2 дня (3 дня); clamp 1–3 дня | то же + понятная ошибка при неверном диапазоне |
| Транспорт | `#transport` | `car` по умолчанию; `foot`, `bike`, `transit` | добавить «не важно»; учитывать в подсказках |
| Кнопка «Собрать маршрут» | `#go` | POST SSE; disabled на время; при ошибке показывает demo | disabled + ошибка/повтор, без demo-подмены |
| Чипы примеров | `.chip` | только заполняют `#q`, не отправляют | либо заполнять, либо сразу запускать — выбрать одно |
| «Токен доступа» | `#token-box` / `#token` | скрыт, если `auth_required:false`; значение в localStorage; заголовок `x-app-token` | показывать только при `APP_TOKEN`; кнопка «Выйти» |
| Вкладки дней | `.tab` | переключают день; подпись из `day.title` | оставить; клавиатурная навигация |
| Карточка точки | `.stop` | клик — flyTo маркера; показывает время, название, `place_id` | оставить; раскрывать описание/источник |
| Где остановиться | `#lodging-box` / `.lodge` | все `plan.lodging_options`; выбранный вариант и первый рекомендацией | оставить; ссылка на бронирование/цену за все ночи |
| Маркеры | Leaflet | нумерованные, fitBounds по точкам дня | кластеризация при >20 точках |
| Линия маршрута | Leaflet | прямая через координаты точек | реальная геометрия OSRM (`legs[].geometry`) |
| Карта | `#map` | OSM tiles, zoom +/−, `invalidateSize` при resize | fallback tiles/offline; кнопка «на весь экран» |
| Атрибуция | Leaflet control | **удалена по запросу** | OSM-кредит остаётся в футере (лицензия) |
| Проверки | `#checks` | `Проверки пройдены: 15/15`, чипы Vxx | фильтр hard/soft; объяснение каждого Vxx |
| Trace | `#trace-box` | JSON tool calls, без раскрытия деталей | человеческие названия шагов; сворачивать |
| Отказ | `#refusal` | текст отказа, план скрыт | кнопка «Попробовать пример» |
| Футер | `.foot` | OSM, Open-Meteo, OSRM | оставить; ссылки на лицензии |

## Отели

Если инструмент `find_lodging` вернул варианты, бэкенд отдаёт **все** варианты в
`plan.lodging_options`, а выбранный — ещё и в `plan.lodging` / `days[].lodging_id`.
UI показывает список «Где остановиться»: номер, название, населённый пункт, тип,
цену за ночь, метки «рекомендация» и «в плане». Если вариантов нет — секция
скрывается. Бронирования и внешних ссылок пока нет.

## Состояния

- **Пусто** — форма и карта Приморья; результатов нет.
- **Загрузка** — stages: «Проверяю тему → Разбираю запрос → Собираю план → Проверяю план → Готово».
- **План** — title, summary, meta (даты, транспорт, км, стоимость, погода, ночёвка, предупреждения), tabs, stops, checks, trace.
- **Отказ** — блок `#refusal`, без плана; HTTP при этом 200.
- **Ошибка** — сейчас **демо-план** (это заглушка, не продакшн-поведение).
- **Токен** — поле скрыто, пока `/api/health` не вернёт `auth_required:true`.

## Что удалено по запросу

- Бейджи `мок` у точек и ночёвки.
- Бейдж `mock-llm` в шапке; вместо него `онлайн`.
- Контрол атрибуции Leaflet «Leaflet | © участники OpenStreetMap».
- OSM-кредит при этом остался в футере — этого требует лицензия ODbL.
- Поле «Токен доступа» скрыто, если токен на сервере не задан.

## Что должно быть в API для UI

`POST /api/plan` и `/api/plan/sync` принимают:

```json
{
  "query": "хочу к морю и маякам",
  "start_date": "2026-10-22",
  "end_date": "2026-10-24",
  "transport": "car"
}
```

- Даты необязательны, но передаются вместе; диапазон 1–3 дня.
- `transport`: `car`, `foot`, `bike`, `transit`.
- Если даты не переданы, intent парсится из текста (по умолчанию 2 дня).
- `GET /api/health` отдаёт `auth_required`, чтобы UI не показывал токен зря.
- План отдаёт `days[].items[]`, `days[].legs[]`, `weather[]`, `warnings[]`, `sources[]`,
  `lodging[]` (выбранное) и `lodging_options[]` (все варианты для блока «Где остановиться»).

## Чек-лист ручной проверки

1. Открыть `/`, карта Приморья видна, zoom +/− работают, атрибуции Leaflet нет.
2. Ввести «Хочу к морю и маякам», оставить даты по умолчанию — план на 3 дня.
3. Сменить транспорт на «Пешком» — в meta и в intent транспорт `foot`.
4. Сменить даты на 1 день — план на 1 день, даты совпадают.
5. Ввести «Реши задачу по алгебре» — отказ, плана нет.
6. Задать `APP_TOKEN` на сервере — поле токена появляется; без него — скрыто.
7. Открыть trace — видны tool calls и validation.
