# Parser: адаптеры и мок-данные

Модуль `src/parser` отвечает за получение, нормализацию и проверку внешних данных для планировщика.

## Зона ответственности

- адаптеры источников: геокодер, погода, достопримечательности, жильё, транспорт, топливо, события;
- приведение ответов к внутренним моделям домена;
- мок-данные и фикстуры для демо и тестов;
- проверка обязательных полей, диапазонов координат и допустимых значений.

## Идентификаторы и координаты

- Стабильный id: `mock:place:N`, `mock:lodge:N`, `mock:trip:N`; live-источники получают id от провайдера и не меняют его между запросами.
- `lat`/`lon` — WGS84, в JSON всегда порядок `lat`, `lon`; в GeoJSON — `[lon, lat]`.
- Координаты проверяются по bbox Приморского края: lon 130.0–139.1, lat 42.2–48.5.

## Нормализация

- `opening_hours` — строка вида `Tu-Su 10:00-18:00` или `24/7`; `null`, если режим неизвестен.
- `source` — только `live`, `cache`, `mock` или `stale`; мок-объекты всегда помечаются `mock`.
- Цены — целые рубли, время — `HH:MM`, даты — ISO 8601.

## Надёжность и безопасность

- Таймаут одного внешнего запроса — 8 секунд; при ошибке используется кэш или `stale`.
- TTL кэша: погода — 30 минут, места/жильё/транспорт — 24 часа, геокодирование — 7 дней.
- Пользовательские URL не принимаются: только allow-list провайдеров, защита от SSRF.
- Ответы провайдеров не доверенные: проверять схему, размер и типы до записи в домен.

## Мок-данные

- `data/mock/places.json`, `lodging.json`, `transport.json` — только для демо и eval.
- `data/eval/*.jsonl` — запросы и guardrail-кейсы; `data/geo/primorye.geojson` — упрощённый контур.
- Мок-ответы нельзя выдавать за live; в UI и логах указывать `source: "mock"`.
